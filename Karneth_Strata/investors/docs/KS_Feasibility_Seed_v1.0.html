§2 · Technology feasibility

2The demonstrator is real, and it works

The Karneth Strata command layer exists today as a running simulation platform with hardware-in-the-loop integration. It is not a slide deck; it is a system that an operator can sit down at, command a mixed fleet from, and watch execute autonomous missions in real time. The same code path that runs the simulator drives the live robotic-platform integration used for partner demonstrations.

What is demonstrable today

Single-operator multi-platform command

One operator station commanding mixed air and ground unmanned platforms through a unified tactical map, with autonomous mission execution and operator-by-exception intervention.

Emissions-controlled (EMCON) operation

Full operator displays continue to function under enforced radio silence — every shown value is gated to transmitted-only telemetry, validated end-to-end against an independent audit pass. Defence-grade communications discipline, not a screensaver effect.

Resilient mesh datalink

The platform-to-platform communications layer (BURST MESH) sustains command coherence when individual links are degraded or jammed. State is propagated as transmitted serialised diffs, not as shared simulator memory — the architecture is portable to real radios.

Hardware-in-the-loop integration

Live robotic integration with PiDog-class ground platforms, including audio direction-of-arrival sensing, distributed kill-chain coordination, and operator-grade after-action review. Demonstrable to visiting partners.

The reviewer can take three things from this. First, the architectural risk is bounded — the hard problems (mixed-platform command, EMCON-coherent operator displays, resilient mesh communications) are not future work, they are demonstrable. Second, the team's engineering discipline shows in the codebase — explicit safety clamps, embedded-grade allocation discipline, audit trails by construction. Third, the path from simulator to fielded system is short because the simulator was built from the start to share code with the real system, not as a separate prototype.

The Technical Pack provides specific evidence for each claim above — code references, demonstrator screenshots, telemetry traces, and the auditing methodology used to verify EMCON discipline.

§5 · Sovereign feasibility

5The sovereign positioning is engineered, not branded

European defence procurement is moving rapidly away from Chinese-controlled supply chains and US-hosted AI inference. The political pressure is real and irreversible; the supply alternatives are scarce. Karneth Strata is one of the few European defence-software ventures whose architecture is sovereign from the foundation rather than retrofitted around it.

That foundation has four parts, each of which is engineered rather than asserted:

  1. Software. Codebase developed entirely in-house by the KS engineering team. No third-party autonomy-stack dependencies that originate in non-aligned jurisdictions.
  2. AI methodology. The Lead-Box methodology (Investor Brief §5) keeps models, weights, prompts, source code, mission data, and customer payload local. UK MoD, US ITAR, NATO equivalents, and most primes' subcontract terms forbid customer-touching code from being processed by US-hosted AI APIs. KS can bid on this work; most AI-augmented startups cannot.
  3. Hardware integration. Platform-agnostic command layer. Customers choose their own airframes, ground platforms, and maritime hulls from aligned suppliers. KS does not lock the buyer to a single hardware vendor.
  4. Industrialisation discipline. Production ramp planned to Swiss / European industrial standards under a COO whose entire career is European industrial scale-up. Not a contract-assembly play.

The result is a procurement story that is easy for a defence buyer to sign off internally: every layer of the stack is in jurisdictions the buyer can actually inspect, audit, and regulate. This is what European procurement leaders have been asking suppliers for. Few suppliers have it.
